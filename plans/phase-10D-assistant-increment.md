## Context and answer contract

Sources have server-defined ID, label, text, version and safe internal or approved catalog link. FAQ IDs resolve to `/help#...`; catalog IDs resolve to a new read-only `/assistant/sources/<id>` page which renders bundled attributed data, including illustrative currency/cost. No arbitrary client/model URL. Prefer FAQ sources without catalog access; catalog failure leaves FAQ fallback working. Citation existence alone is insufficient: model output is restricted to a bounded JSON source-ID selection, with answers rendered as exact source excerpts. Unknown IDs or extra fabricated text are rejected. Instructions in questions/catalog are untrusted and cannot gain tools or authority.

Trip context is opt-in per request (stricter than remembering session consent), exactly one selected ID from the trusted account-trip gateway. Recheck authorization before every dispatch and before returning output; expiry/revocation/deletion/ownership loss discards late results. With no selection send no trip, even if the user browsed a trip page. Gateway is read-only and not an anonymous-save adapter. No guest row claiming is implied. Project only destination, allowed preferences, itinerary venue/slot/illustrative estimate fields; no trip title, email, account/row IDs, cookies, tokens or arbitrary free text. Reject overlarge context; do not truncate away rules. Production gateway remains absent until real account ownership/claiming is implemented and tested.

Each request is a single conversation turn. No application transcript, browser local/session storage or transcript in signed cookies. Optional JS displays up to four turns in DOM only, clears on navigation/clear and sends no history to the provider. Zero prior turns is within the four-turn ceiling. Current source has no real logout endpoint; no-store plus clearing DOM on pagehide and authority revalidation are defense in depth, not proof of browser Back-cache behavior.
